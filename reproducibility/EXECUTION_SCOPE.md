# Source and execution scope

## Verified from the available archives

- Preserved source-file identities in `SOURCE_LOCK.csv`, including 15 terminal-source fingerprints.
- The three-family training source and preprocessing/splitting code used for the Bank, Electricity and Gas development suite.
- Original algorithm sources and component experiment runners covering sparse maintenance, resource certification, Temporal Actionability, high-information repair, multiclass transfer and preservation.
- Exact plotting-code inputs and the bundled final figure PDFs.
- Dataset catalog with direct source references and fingerprints where present.

## Not certified by the collected evidence alone

- One unified end-to-end command that trains all ten principal streams plus the three separately locked sparse-confirmation streams and then reproduces every component-level claim.
- Independent matching run for every backbone, seed and comparator.
- Automated source-to-input selection for all terminal RACS intermediate files (including `CPPI_GREG_SELECTED_ALL_SIX.csv` and `BOSA_SELECTED_DEPLOYMENT_SEEDWISE.csv`).
- Model generation for the complete high-information rolling-endpoint protocols and all preserved source-guard inputs.
- Exact acquisition/processing of every stream where the source provides a public landing page but not a pinned materialized dataset checksum.
- Independent third-party software authorship/licensing review.

The source lock establishes byte-level identity, not empirical equivalence between different runs. Trained endpoints may be kept locally as execution artifacts; they are not required as files in the distributed source package. To claim reproduction within specified tolerances, execute the full data/training/controller/evaluation chain and compare its outputs against `expected/` using the protocol declared for each experiment.
